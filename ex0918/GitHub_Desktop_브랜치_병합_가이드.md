# GitHub Desktop으로 브랜치 병합하기

이 문서는 이 폴더의 Git 저장소에서 서로 다른 브랜치의 작업을 **GitHub Desktop**으로 병합(merge)하는 방법을 정리합니다.

> 예시: `feature` 브랜치의 변경 사항을 `main` 브랜치에 합치는 경우

## 병합 전 확인

- 병합할 두 브랜치의 변경 사항을 모두 커밋합니다.
- 병합 대상 브랜치(예: `main`)가 최신 상태인지 확인합니다.
- 공동 작업 중이라면, 병합 전에 팀원에게 알려 같은 파일을 동시에 수정하는 일을 줄입니다.

## 빠른 흐름

```text
병합을 받을 브랜치 선택 → Fetch origin/Pull → Branch 메뉴에서 병합할 브랜치 선택
→ 충돌 해결(필요 시) → 커밋 확인 → Push origin
```

## 단계별 방법

### 1. 저장소 열기

1. **GitHub Desktop**을 실행합니다.
2. 상단의 **Current repository**에서 이 프로젝트 저장소를 선택합니다.
3. 목록에 없다면 **File → Add local repository**를 선택하고 이 폴더를 지정합니다.

### 2. 변경 사항을 먼저 커밋하기

1. 왼쪽 **Changes** 탭에 저장되지 않은 변경이 있는지 확인합니다.
2. 변경 내용을 확인한 뒤, 아래의 **Summary**에 커밋 메시지를 입력합니다.
3. **Commit to `<현재 브랜치>`**를 클릭합니다.

병합 전에는 양쪽 브랜치 모두 커밋되어 있어야 작업 내용을 안전하게 추적하거나 되돌릴 수 있습니다.

### 3. 병합을 받을 브랜치로 이동하기

가장 중요한 순서입니다. **변경 사항을 받을 브랜치**를 먼저 선택해야 합니다.

예를 들어 `feature`의 내용을 `main`에 합치려면:

1. 상단의 **Current branch**를 클릭합니다.
2. 목록에서 **`main`** 브랜치를 선택합니다.
3. 상단의 **Fetch origin**을 클릭합니다.
4. **Pull origin**이 표시되면 클릭하여 원격 `main`의 최신 변경 사항을 받습니다.

### 4. 다른 브랜치 병합하기

1. 메뉴에서 **Branch → Merge into current branch...**를 선택합니다.
2. 병합할 브랜치(예: **`feature`**)를 선택합니다.
3. 표시되는 변경 파일과 병합 방향을 확인합니다.
4. **Merge `<브랜치 이름>` into `<현재 브랜치>`**를 클릭합니다.

`main`을 현재 브랜치로 선택한 상태에서 `feature`를 병합했다면, 결과는 다음과 같습니다.

```text
feature ──▶ main
```

### 5. 충돌(conflict)이 발생했을 때

같은 파일의 같은 부분을 두 브랜치에서 다르게 수정했다면 충돌이 생길 수 있습니다.

1. GitHub Desktop의 충돌 안내에서 해당 파일을 엽니다.
2. 충돌 표시(`<<<<<<<`, `=======`, `>>>>>>>`) 사이의 내용을 검토합니다.
3. 남길 내용을 직접 정리하고 파일을 저장합니다.
4. GitHub Desktop으로 돌아와 **Mark as resolved**를 선택합니다.
5. 모든 충돌을 해결한 뒤 **Continue merge** 또는 병합 커밋 버튼을 클릭합니다.

충돌 내용을 확신할 수 없다면 임의로 한쪽을 삭제하지 말고, 두 변경 사항의 의도를 먼저 확인하세요.

### 6. 원격 저장소에 올리기

병합이 완료되면 상단의 **Push origin**을 클릭합니다. 이 단계를 완료해야 GitHub 원격 저장소에도 병합 결과가 반영됩니다.

## 병합 후 확인 목록

- [ ] 현재 브랜치가 의도한 대상 브랜치인가? (예: `main`)
- [ ] 병합하려던 브랜치의 파일 변경이 포함되었는가?
- [ ] 충돌 파일이 남아 있지 않은가?
- [ ] 필요한 실행 또는 테스트가 정상 동작하는가?
- [ ] **Push origin**까지 완료했는가?

## 실수했을 때

병합 직후이고 아직 원격 저장소에 올리지 않았다면 GitHub Desktop의 **Repository → Undo**로 최근 병합을 되돌릴 수 있는 경우가 있습니다. 이미 원격에 올렸거나 다른 사람이 변경을 받았다면, 단순히 강제로 되돌리지 말고 팀의 작업 방식에 맞춰 새 커밋으로 되돌리는 방법을 사용하세요.

## 용어 정리

| 용어 | 의미 |
| --- | --- |
| 브랜치(branch) | 독립적으로 작업을 진행하는 작업 흐름 |
| 병합(merge) | 한 브랜치의 변경 사항을 다른 브랜치에 합치는 작업 |
| 현재 브랜치 | GitHub Desktop에서 선택되어 있으며, 변경을 받는 브랜치 |
| Fetch / Pull | 원격 저장소의 최신 정보를 확인 / 내려받는 작업 |
| Push | 로컬 커밋을 원격 저장소에 올리는 작업 |
| 충돌(conflict) | 두 변경이 자동으로 합쳐지지 않아 사람이 선택해야 하는 상태 |
